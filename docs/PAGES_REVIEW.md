## 2. `/exchanges12/` 12 家总览 —— ~~未生成~~，当时卡在哪（2026-08-07 已按降级规则生成，见文首追记）

`build/exchanges12.py` 跑完打印的原因（原文摘要）：**12 家总览页只在全部成员都能换算成

我核了一遍 CSV，这条拦截是对的：73 个产品里**只有 23 个有 `base_notional_per_unit_local`**，
其中 14 个是「本来就是金额」的池（现货成交额、募资额、AUM、FX 即期，乘数 = 1），
真正的合约类只有 9 个（Cboe SPX / VIX / VIX 期权 / XSP、CME MES、CME SR3 / ZB / ZF / ZN）。
缺的 50 个里，卡在总览页路上的是这几个篮子：
`US_CASH_EQUITY_SHARE`、`US_MULTILIST_EQ_OPT`、`SGX_DERIV`、`MX_STIR`、`MX_ETF_OPT` 等。
`series/contract_specs_todo.csv` 登记了 21 条阻塞原因（CME 规格表交给前端 JS 渲染、
CmeWS API 返回 IP 封禁；Eurex 与 ASX 的规格页是纯 JS 外壳）。

按 `product_id` 归并后，卡住总览页的是 **25 个**（同一个产品被多家引用只需填一次）：
CME 5 个（RATES / EQUITY_INDEX / ENERGY / AG / FX）、ICE 3 个（ENERGY / STIR / MLTIR）、
Eurex 3 个、Euronext 3 个、MX 4 个、ASX 2 个、HKEX / JPX / SGX 各 1 个，
外加两个被多家共用的美国池：`US_MULTILIST_EQ_OPT`（Cboe / ICE / MIAX 引用）与

`/exchanges-na/` 也能同时画出美元名义额（现在它只画得出份额与增长）。
篮子类产品的常数 = Σ(成员合约 2019-01 张数 × 乘数 × 基期价格) ÷ Σ(成员 2019-01 张数)，只算一次写死。

**第二轮新增的 Ex16–19，两条口径要记住：**

- **Ex16/17 的季度值是量加权，不是三个月月份额的平均。**
  `Σ(当季各月 ADV × 当月交易日) ÷ Σ(当季各月行业 ADV × 同一批交易日)`，等价于把一个季度
  当成一段连续日历来算份额。独立复算过三个季度（2026Q2 / 2019Q4 / 2015Q3），
  payload 与量加权逐位相同、与简单平均处处不等（最大 2.0bp）。只认三个月齐全的整季，
  所以最后一季是 2026Q2 而不是只有一个月的 Jul-26。

Ex4（期权池份额变化）、Ex8（现货池份额变化）、Ex13（自校验残差）三张图都用的
`diverging_bars`，交易所份额页上会凭空出现「油汇」两个字。
引擎不能动（14 页共用，改一行要重新验收 14 页），所以**改的是 build 脚本**：
三张图换成**只放一个 group 的 `grouped_bars`**，图例名与表格列名都能自定义，
纵轴 `y0 = min(0, mn×1.15)` 照样容纳负柱；`bar_labels` 显式打开（该 kind 默认是关的）。
不能用 `bars_labeled` 代替 —— 它强制零基线，负柱会被画到画布外。

**代价：正负分色没有了**，三张图现在都是单色 NAVY。Ex4 / Ex8 按变化降序排，
正负分界一眼就在，损失有限；Ex13 是 187 根残差柱，本来也不靠颜色读。
若认为分色不可少，唯一出路是给引擎新增一个不带 COST 文案的分色柱 kind ——
那要重新验收 14 张老页，成本远大于收益，所以没做。

浏览器复验（改后重跑并重新打开页面）：Ex4 图例是「份额变化 Jan-25 → Jul-26（pp）」、
Ex8 是「份额变化 Dec-20 → Jul-26（pp）」、Ex13 是「残差 = ICE 自报份额 − 本页重算份额（bp）」，
柱数 5 / 5 / 187，**全页搜不到「油汇」也搜不到「Reported」**。
设计文档里给 `/exchanges12/` 排的 Ex3 / Ex7 用的也是这个 kind —— 实际生成出来的
`/exchanges12/` Ex3 / Ex5 / Ex6 已经是 `grouped_bars`，同一个坑不会再踩第二次。
详见 `docs/CHART_KINDS.md` §3.4。

**5. `verify_pages.py` 的多线图判据本轮收紧了一次，顺带说明。**
原判据是「`lines` 的线数 > 5 就警告」，会误报：数据色恰好有 6 个
（NAVY / BLUE / MBLUE / GRAY / GREEN / GOLD），「5 家 + 其余合计(GRAY)」这种横截面图
正好用满 6 色、每条都不撞，是可读的（当时 `/exchanges-intl/` Ex2 就是，该页已删）；
而真正的缺陷 —— **两条线同色、读者根本分不开** —— 反倒不在判据里。
现在判据换成「颜色有没有真撞上」+「条数是否超过 6」，并把 `lines_endlabels` 一并纳入
（原来只查 `lines`，而 `/exchanges12/` Ex2 恰好是 6 条线的 `lines_endlabels`，漏在判据外）。
`year_lines` 不查 —— 它的颜色由引擎按年份明度阶自动分配，payload 给不给都不算数。
改完全仓 16 个 payload 仍是 0 ERROR，那条误报消失。
