## 四、原文没想到、但会实质影响结论的问题

### N1　商品関連在宽表里被 pro-forma 回填到 1985 年，而 JPX 当时并不拥有 TOCOM

宽表 `商品関連` 列**从 1985-10 就有数**：

```
1985-10  商品 341,027 / 总 545,924 = 62.5%
2016-06  商品 2,527,134 / 总 34,585,815 = 7.3%
2019-06  商品 2,002,223 / 总 33,025,907 = 6.1%
2026-06  商品   812,336 / 总 52,044,377 = 1.6%
```
而长表 `金標準先物` 的**首月是 2020-07**。两表不是"精度差异"，是**范围差异**：
旧 TOCOM 品种 2020-07-27 才迁入 OSE，JPX 2019-10 才完成对 TOCOM 的收购。
宽表把 TOCOM 的历史**追溯并入 JPX 口径**，长表如实从迁入日开始。

原文口径坑 6 只讨论了 2020-07 的半月问题，并**明确建议 `adv_deriv_cmdty_kcontracts` 取宽表**，
完全没提这条。后果：任何从 2015/2016 起画的"JPX 衍生品总量"曲线，
都会把 JPX 当时没有的商品业务算进去，**并把 2020 年那次收购带来的台阶抹平**。
横截面对比里这等于替 JPX 虚增了 6–7% 的历史体量。

### N2　`adv_deriv_total_kcontracts` 是原始张数，**它的时间趋势方向是错的**

这是本次复核最重要的一条。JPX 自己的 IR 第 5 页印的
`Financial Derivatives 23 mil. Contracts (Q1FY2026) / 24 mil. (Q1FY2025)`——
我按 IR 脚注的 1/10、1/100 折算（mini / micro / ミニTOPIX / ミニJGB / 日経225ミニオプション）
重算得 **23.6 mn / 24.6 mn**，与 IR 吻合；而**原始求和是 121.2 mn / 107.3 mn**，差 **5 倍**。
商品同理：IR 印 `141 / 349`（万张），原始是 `227 / 469`（万张）。

⇒ **JPX 自己从不把原始张数当作总量口径。** 原文只为日経225 复合体建了大合约当量
（`adv_n225_lgeq_kcontracts`），却让全所总量与三大类小计走原始张数。

更严重的是，原始/当量的倍率**不是常数，而是单调走高**：

```
month     raw ADV(千张/日)   大合约当量(千张/日)   raw/当量
2016-06        1572               723              2.17x
2019-06        1651               735              2.25x
2023-04        1207               412              2.93x
2023-06        2039               761              2.68x
2025-06        1513               479              3.15x
2026-06        2366               524              4.52x
```
（当量列是我按上述折算自建的，已用 IR 季度值校准到 ~2% 以内，非官方逐月发布值）

**2016-06 → 2026-06：原始张数 1572 → 2366，+50%；大合约当量 723 → 524，−28%。
同一个业务，两个口径的十年趋势**符号相反**。** 原文口径坑 1 只说"跨所比较前先读"、
"原始张数只用于 JPX 自身的时序图"——而**恰恰是 JPX 自身的时序图上这个序列会讲反话**。

### N3　长表每个期权品种是 `プット` / `コール` / `合計` 三行，naive groupby 会翻倍

我自己踩了：对 `soukatsu_M.xlsx` 按 (产品, 年月) 求和，日経225オプション 月末 OI 得

### N4　`adt_cash_total_jpytn` 与 `mktcap_eom_jpytn` 的统计范围不一致

- ADT 分子 = 内国株 + **外国株** + **内国ETF + 外国ETF/ETN + 内国投資証券(REIT)**
- `historical-jika.xlsx` 的列只有 `プライム / スタンダード / グロース / TOKYO PRO`，
  即**上市股票**，**不含 ETF / REIT**

所以 `换手率 = ADT×days / mktcap` 会系统性高估。原文把这两列并列却没写这一条。

   我用上述规则算出 23.6 / 24.6，误差 ~2%，说明规则大体正确但**折算表要以 JPX 合约规格页复核后写死**，

## 七、最终判定

**A（维持）。**

理由：判定轴是"能否直接实现"。抓取端零障碍（我自己不设 UA 全通、robots 全放行、HEAD 可用、
无任何第三方源、无登录态）；解析端全部确定性，我自己重写解析器把原文每一个数字都算了出来；
历史深度真实且我远程抓了一期 2019 年文件验证过；两条独立管道的交叉核对我都亲自重做并全部对上。
按原文自己的 B 标准（"需要降级方案或人工介入"），JPX 一条都不占。

**但这是一个附条件的 A**：第六节 1–4 条不是优化建议，是**必须在实现前修正的字段规格缺陷**。
按原文现在写的 26 列直接落地，会产出一条趋势方向与真实业务相反的门面序列（N2），
以及一段把别人家业务算作自己的历史（N1）。抓取侦察合格，字段设计未合格。
