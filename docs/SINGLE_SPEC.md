# `build/single.py` 的 SPEC 契约 —— 一家一份配置，写给下一个加新页的人

底座：`build/single.py`（通用，不认得任何一家）
配置：`build/specs/<ticker>.py`（一家一份，只有数据，没有逻辑）
产物：`data/<ticker>.js`（payload 与既有 12 家同构，由 `assets/page.js` + `assets/charts.js` 渲染）

```
python3 build/single.py ice            # 建一家
python3 build/single.py ice ndaq db1   # 建几家
python3 build/single.py --all          # build/specs/ 下全部
```

## 0. 一家 = 一份文件，删得干净

新增一家只需要**加一个文件**；删除一家只需要**删三样东西**：

```
build/specs/<t>.py      配置
data/<t>.js             产物
<t>/index.html          页面壳
```

再从导航名单（`build/roster.py`）里去掉那一行，仓库里就不留任何残渣。

底座里**没有、也不许有 `if ticker == 'xxx'`**。任何一家的特殊处理只有两个去处：
写进它自己的 spec（字段能表达的部分），或者写一个独立的 hook 文件（字段表达不了的部分）——
不要往 `build/single.py` 里塞分支，那等于把「随时可以删掉某几家」这条前提废掉。

## 1. 字段契约

一份 spec 就是一个名为 `SPEC` 的 dict。**字段名由主线程定死，不许自行更改**；
写了未知字段会**硬失败**（拼错的字段被静默忽略，比报错危险得多）。

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `ticker` | ✓ | str | = 目录名 = data 文件名 = `payload.ticker`，三者逐字相同。只许小写字母/数字/连字符 |
| `name` | ✓ | str | 英文短名，抬头（`tracker`）与页脚用 |
| `title` | ✓ | str | 页面大标题。底座会自动接上「 — YYYY 年 M 月」 |
| `csv` | ✓ | str | `series/` 下的文件名 |
| `ccy` | ✓ | str | 本币，只做标注；跨币种换算不在本页做（`build/notional.py` 的事） |
| `source` | ✓ | str | 图脚 `Source:` 行，全页共用 |
| `headline` | ✓ | list | 1–3 条列配置。**决定本页共同最新月与发布门槛** |
| `groups` | ✓ | list | 每组 `{'zh': 组名, 'cols': [列配置…]}` |
| `slow_cols` | | list[str] | 慢腿列名（发布比头条晚）。**不参与门槛计算**，最新月留空是正常的 |
| `breaks` | | list \| str | 口径断点。给列表字面量，或给 `series/` 下一张断点表的**文件名** |
| `notes` | | list[str] | 追加到「口径与方法说明」末尾的自定义条目，允许 HTML。用 `<b>…</b>` 加粗；写成 Markdown 的 `**…**` 会被底座自动换成 `<b>`（notes 走 innerHTML，星号原样印在页面上），换了几条会在跑的时候打印出来 |
| `decomp` | | list | 量价分解图（一条一张，见 §1.3）。**追加在全部既有 exhibit 之后** |
| `ttm_yoy` | | list | 「水平值 + 12 个月滚动同比」图（一条一张，见 §1.4）。同样追加在末尾 |
| `headline_style` | | str | 头条列的开篇画法。缺省 `'band_yoy'` = 两张（①全历史折线 + 近 3 年 P10/P90 分位带、②单月同比柱）；`'bar_yoy'` = **一张**（全历史的水平值柱 + 次轴单月同比折线）。⚠️ 选 `'bar_yoy'` 就等于把分位带从页面上拿掉 —— 引擎没有「柱 + 两条带 + 次轴线」这种图型，带的上下沿与柱同量纲、画上去会被读成第三根柱。汇总表的「3Y %ile」列不受影响，页尾那句「Exhibit N 的灰色分位带与它同窗口同口径」会自动收掉，不留指着不存在的图的话 |

`groups[]` 每项是 `{'zh': 组名, 'cols': [列配置…]}`，另有一个可选的 `mix`（见 §1.5）。

### 1.1 列配置

```python
{'col': 'adv_eurex_rates_kcontracts',   # CSV 里的列名，写之前 head -1 核对
 'zh':  '利率',                          # 中文短名，进图例/表头/图注
 'unit': 'k contracts/day',              # 单位串，进 ylab 与表头
 'fmt': 'f0',                            # 引擎实有的 18 个格式器之一
 'stock': True,                          # 可选，缺省 False = 流量
 'scale': 100}                           # 可选，缺省 1.0
```

| 键 | 必填 | 说明 |
|---|---|---|
| `col` | ✓ | 必须真实存在于 `series/<csv>`，否则硬失败 |
| `zh` | ✓ | 中文短名。热力矩阵的行标签宽度按它自动算 |
| `unit` | ✓ | 单位。**同一张图只放同一 `unit` 的列**，底座按它自动分桶 |
| `fmt` | ✓ | 见 §4 的 18 个名字。引擎对不认识的名字**静默退回 f1**，所以底座硬校验 |
| `stock` | | `True` = 存量（期末截面值，跨币种配月末汇率）；缺省 = 流量（日均或月总，配月均汇率）。存量列**单独成图**，不与流量列共轴 |
| `scale` | | 恒等换算系数。唯一常见用途：源表存的是 0–1 的小数比率，而 `pct*` 格式器期望百分数刻度（29.0 → `29%`），此时写 `'scale': 100` |

### 1.2 `breaks`

两种写法，任选：

```python
'breaks': [{'month': '2025-11', 'zh': '并入雅典交易所'}],              # 字面量
'breaks': [{'month': '2025-11', 'zh': '…', 'col': 'adv_cash_trades_k'}],  # 只标在画了这一列的图上
'breaks': 'enx_breaks.csv',                                            # 从 series/ 读（推荐）
```

**能读 CSV 就读，别写死**：断点本来就跟着数据走。CSV 的列名认
`month` / `break_month` 与 `zh` / `footnote` / `note` / `official_footnote`，
可选 `col` / `column`。同一 (月份, 列) 重复登记会自动去重。

断点在**横轴是月份**的图上画成红色竖虚线，位置在该期的**左缘**，语义是
「从这一期起与左侧不可比」。落在窗口第 0 格的断点不画（左缘就是画布边线，读不出来）。
`heat_matrix` 不支持断点线（矩阵没有连续横轴），底座会在「口径与方法说明」里交代。

### 1.3 `decomp` —— 量价分解（恒等式 金额 ≡ 数量 × 派生量）

一条 = 一张 `bridge_bar`，横轴一格是一个**完整年度**，把金额的年度增长拆成
「量的贡献」与「派生量的贡献」两块，两块相加**逐格等于**菱形标的总增长。

```python
'decomp': [{
    'zh':   '东证内国株现货成交额',     # 图题里的业务名
    'kind': 'share_price',              # ← 必填，三选一，见下表
    'granularity': 'daily_avg',         # ← 必填：列是当月日均还是当月合计
    'value': {'col': 'adt_cash_dom_stocks_jpytn', 'zh': '内国株成交额',
              'unit': '¥tn/day', 'fmt': 'f1'},        # 列配置，同 §1.1
    'qty':   {'col': 'adv_cash_dom_shares_mn', 'zh': '内国株成交股数',
              'unit': 'mn shares/day', 'fmt': 'f0c'},
    'value_total_col': 'val_cash_dom_stocks_jpytn',   # 可选：源表自带的当月合计列
    'qty_total_col':   'vol_cash_dom_shares_mn',      # 可选：同上
    'weight_col':      'trading_days',                # 可选：日均 × 它 = 当月合计
    'price_zh':    '加权平均成交价',    # 派生量的中文名（进图例与图注）
    'price_unit':  '円/株',
    'price_fmt':   'f0c',
    'price_scale': 1e6,                 # 可选，缺省 1.0：纯单位换算，**对增长率无影响**
    'year_start_month': 4,              # 可选，缺省 1（日历年）；4 = 4 月制财年
    'year_label': 'start',              # 可选，缺省 'start'；SGX 那种要写 'end'
    'years': 5,                         # 可选，缺省 5：画几根柱（需要 years+1 个完整年）
    # 下面两个**同时给或同时不给**：给了就从两块柱变三块（行业 / 份额 / 结构）
    'bench_value': {'col': 'industry_adnv_…', 'zh': '全美股票行业成交额', …},
    'bench_qty':   {'col': 'industry_adv_…',  'zh': '全美股票行业成交股数', …},
    'share_zh': '成交股数份额',          # 可选：三分法第二块的名字，缺省由 qty.zh 拼
    'mix_zh':   '均价相对行业（品种结构）',  # 可选：第三块的名字
    'note': '…',                        # 可选：本家专属的口径交代，追加在底座图注之后
}],
```

| 键 | 必填 | 说明 |
|---|---|---|
| `zh` | ✓ | 业务名，进标题 |
| `kind` | ✓ | `share_price` / `per_trade` / `revenue_rate`，见下表。**写错类别 = 图注在说谎**，所以必填不给缺省 |
| `granularity` | ✓ | `'monthly_total'`（列本身就是当月合计，如 SGX 的 `sec_turnover_*`）或 `'daily_avg'`（列是当月日均，如 JPX 的 `adt_*`/`adv_*`、MIAX 的 API 四列）。**必填、无缺省** —— 底座猜不出来，猜错就会在图注里印出一句关于口径的假话，而 `verify_pages.py` 只看 payload 结构、查不出这种错。声明 `monthly_total` 却又给 `weight_col` 会硬失败（再乘一次交易日数会把年度合计放大二十几倍，而图形照画） |
| `value` | ✓ | 金额列配置（`col`/`zh`/`unit`/`fmt`，同 §1.1） |
| `qty` | ✓ | 数量列配置 |
| `value_total_col` / `qty_total_col` | | 源表自带的**当月合计**列名。年度聚合优先用它 |
| `weight_col` | | 把「日均」还原成当月合计的权重列（立会日数 / 交易日数）。**与 `*_total_col` 同时给时，底座会拿两者逐月对账**，最大相对偏差 > `1e-6` 就硬失败 |
| `price_zh` / `price_unit` / `price_fmt` | ✓ | 派生量（= 金额 ÷ 数量）的名字、单位与格式器 |
| `price_scale` | | 派生量的单位换算常数（兆円 ÷ 百万株 → 円/股要写 `1e6`）。它在分子分母上同时出现，**对分解结果一个数都不影响**，只决定图注里报出来的水平值读数 |
| `year_start_month` | | 年度起始月，1 = 日历年、4 = 日本 4 月制财年、7 = SGX 的 Jul–Jun。缺省 1 |
| `year_label` | | 财年叫哪一年：`'start'`（JPX：FY2025 = 2025-04…2026-03）或 `'end'`（SGX：FY2026 = 2025-07…2026-06）。**猜错会让整排标签集体偏一年而图形完全正常**，没有任何自动判据能发现，所以做成显式字段。日历年不许写 `'end'` |
| `years` | | 画几根柱，缺省 5，最小 2 |
| `bench_value` / `bench_qty` | | 行业（或任何上位盘子）的对照列，**同时给或同时不给**。给了就走三分法，见下 |
| `share_zh` / `mix_zh` | | 三分法第二、三块的中文名，缺省由 `qty.zh` / `price_zh` 拼出来 |
| `note` | | 本家专属口径交代。**里面不许写死数字** —— 要报数就在 spec 里从 CSV 现算再 f-string（`build/specs/jpx.py` 的 `_wedges()` 是例子） |

**`kind` 三类的派生量含义完全不同，措辞由底座生成，spec 不许自己改：**

| kind | 派生量是什么 | 底座会印的「它不是什么」 |
|---|---|---|
| `share_price` | 成交量加权平均成交价 | 含市场涨跌 **+ 成交结构变化**；**不是股价指数的收益率** |
| `per_trade` | 每笔平均成交额 | 衡量**订单碎片化程度**；**把它叫「价」是错的** |
| `revenue_rate` | 单位成交量的实现费率 | 分解的是**收入**不是成交额；与前两类**不可并读** |

**底座保证的六件事**（都不是某一家专属，底座里没有 `if ticker == …`）：

1. **年度端点一律是整整 12 个月的合计**，不是某一个月的点值 —— 拿单月当端点，挑到一个
   异常月就能把归因整个说反。缺月的年度直接丢掉（不按 11 个月折算成 12 个月）；
   只保留末尾**逐年连续**的一段。
2. **「日均」不许跨月直接相加**：各月交易日数不同，直接加等于配错权重。给了
   `weight_col` / `*_total_col` 就先还原成当月合计再逐年求和，年度派生量 = Σ金额 ÷ Σ数量。
3. **图上画对数分解，不画算术分解。** 算术分解 g<sub>V</sub> = g<sub>Q</sub> + g<sub>P</sub>
   + g<sub>Q</sub>·g<sub>P</sub> 的交叉项不是可忽略的余项（量价一涨一跌时它与净增长同量级
   甚至几倍于它），堆叠柱堆不出可读的归因。对数分解 ln(V₁/V₀) = ln(Q₁/Q₀) + ln(P₁/P₀)
   天然可加、无交叉项；再乘 `w = g_V / ln(V₁/V₀)` 换算成百分点，于是**两块相加 = 总增长
   （%）**，纵轴仍是读者熟悉的 `% y/y`。算术分解仍然逐年算出来，连同两法差异写进图注。
4. **四道硬护栏**，任何一条不过就 `raise SystemExit`（退出码 1，旧文件原地不动）：
   ① 算术三项闭合、② 纯对数两项闭合、③ **画在图上的两块相加 == 总增长**、
   ④ 序列化（`LN()` 舍入到 6 位）之后写进 payload 的那组数仍然闭合。①②③ 的阈值是
   `1e-9`，实测残差量级 ~1e-16。
5. **`|ln(V₁/V₀)| < 1e-6` 的那一格整根留空**（两块与菱形一起留空）。此时
   `w = g_V / ln(V₁/V₀)` 是 0/0；解析上它趋于 1、不发散，但数值上两个由大数相减得来的
   小量相除会把有效位吃光，与其印一个算不准的数不如不印。
6. **横轴是年度类别轴** ⇒ `'xrot': 0`，且**不调 `mark_breaks`** —— 断点索引是按月份窗口
   算出来的，扣到年度轴上会把红虚线画到错的柱子上（断点仍在页尾「口径与方法说明」里列着）。

#### 1.3.1 三分法（给了 `bench_value` / `bench_qty` 时）

自家盘子相对一个更大的盘子还能再拆一层。恒等式同样是**定义式**：

```
V ≡ Q × P              s ≡ Q / Q_行业        r ≡ P / P_行业
V_行业 ≡ Q_行业 × P_行业   ⇒   V ≡ V_行业 × s × r
⇒ ln(V₁/V₀) = ln(V_行业₁/V_行业₀) + ln(s₁/s₀) + ln(r₁/r₀)     三块、可加、无交叉项
```

`bridge_bar` 从两块变三块：**行业**（NAVY）/ **份额**（MBLUE）/ **结构**（GREEN）。
读出来的东西两分法给不了：两分法只会说「量 −7.6pp、价 +4.3pp」，三分法能分出
「行业自己在涨 +29.6pp、而自家在丢份额 −43.3pp、品种结构回补 +10.5pp」。

多两条护栏：⑤ 三块对数相加 == 总对数增长；⑥ 重标定后三块相加 == 总增长。阈值同为 `1e-9`。

⚠️ **份额与结构两块的分界依赖 bench 与本家同口径：分子必须是分母的子集。**
换一家用之前先核这一条 —— 不是子集的话「份额」会算出大于 1 的数，
而图上只会显示成一根更高的柱。底座把这句话写进图注，但**它验证不了子集关系**，
那是 spec 作者的责任。

行业对照走**同一条** `monthly_total`（同一套 `weight_col` 与粒度）：
自家按合计、行业按日均的话，份额 `s` 会带一个逐月漂移的假趋势。

**三分法回归基准**：MIAX 的 `adnv_equities_api_usdbn` / `adv_equities_api_mnshares`
配 `industry_*` 两列（日历年、`granularity='daily_avg'`、无 `weight_col`、`years=4`）应得
2022 净 +81.84%：行业 +2.39 / 份额 +130.90 / 结构 −51.45；
2023 +27.89%：−12.63 / +60.68 / −20.15；2024 −0.83%：+16.88 / −4.17 / −13.54；
2025 −3.25%：+29.61 / −43.32 / +10.45。同一份数据的两分法应得
2022 量 +135.76 / 价 −53.92、2025 量 −7.55 / 价 +4.30。

**回归基准**：SGX 的 `sec_turnover_sgdmn` ÷ `sec_turnover_mnshares`
（`year_start_month=7, year_label='end', years=10`）应得
FY2021 量 +30.74pp / 价 −28.35pp（净 +2.39%）、FY2025 −11.80 / +39.34、
FY2026 +32.52 / +2.95。对不上就是底座被改坏了。

### 1.4 `ttm_yoy` —— 量的水平值 + 12 个月滚动同比

一条 = 一张 `gs_bar`：深蓝柱是水平值（原始单位），金色次轴线是
**12 个月滚动合计的同比**。

```python
'ttm_yoy': [{
    'zh': '内国株成交股数',
    'granularity': 'daily_avg',               # ← 必填，同 §1.3
    'level': {'col': 'adv_cash_dom_shares_mn', 'zh': '日均成交股数',
              'unit': 'mn shares/day', 'fmt': 'f0c'},   # 画柱的列，同 §1.1
    'total_col':  'vol_cash_dom_shares_mn',   # 可选：算滚动合计用的当月合计列
    'weight_col': 'trading_days',             # 可选：与 total_col 同时给就互相对账
    'note': '…',                              # 可选
}],
```

**为什么次轴不许用单月同比**：单月同比同时被交易日数、假期与到期日的月度形状、
以及去年同月那一个数的高低推着走，毛刺可以大到与趋势**符号相反**。
底座的图注会**用这条序列自己**实测毛刺量级（两种同比的逐月标准差、相邻月最大跳变并
点名是哪两个月、符号相反的月份占比与差得最远的那个月），不引用别家的数字。

`level` 与 `total_col` 允许不同口径（前者日均、后者当月合计），底座会在图注里说明
「柱与线口径不同是有意的」；两者若同时给了 `weight_col`，底座照样逐月对账。

⚠️ **「滚动更平滑」这个结论由数据判定，不写死。** 有的序列滚动同比的**标准差反而更大**
（序列在单向爬坡时，标准差量到的是趋势幅度而不是噪声）。底座同时报标准差与
**相邻月最大跳变**两个判据：两个都支持就直说，只有跳变支持就点明标准差为什么会反过来，
两个都不支持就明说「本图仍用滚动同比，理由不是更平而是口径 —— 任意连续 12 个月
覆盖同一套日历」。

### 1.5 `groups[].mix` —— 「合计柱 + 分项 100% 占比堆叠」两张图

一条 `mix` = 两张图，**顺序固定、就排在这一组的位置上**（不像 `decomp` / `ttm_yoy`
那样追加到末尾）：

| # | 图型 | 内容 |
|---|---|---|
| 第一张 | `gs_bar` | `total` 那一列的水平值柱 + 次轴同比（流量单月 / 存量点对点，见下） |
| 第二张 | `stacked_dual` | `parts`（+ 可选残差）占 `total` 的比重，每根柱恒高 100% |

```python
{'zh': 'MX 衍生品 ADV', 'cols': [ …三条列配置… ], 'mix': {
    'total': 'mx_adv_contracts',                     # ✓ 列名（不是列配置）
    'parts': ['mx_adv_futures_contracts',            # ✓ 列名，1–4 条
              'mx_adv_options_contracts'],
    'residual_zh': '其他（官方未单列）',              # 有残差时必填
    'rhs_share': 'alpha_value_cad',                  # 可选：把某一段在右轴重画一遍
    'note': '…',                                     # 可选：追加到合计柱的图注
    'share_note': '…',                               # 可选：追加到占比图的图注
}}
```

| 键 | 必填 | 说明 |
|---|---|---|
| `total` | ✓ | **列名**，必须是本 spec 已声明的列（`headline` 或任意 `groups[].cols`，允许跨组引用）。它同时是柱图那条序列与占比图的分母 |
| `parts` | ✓ | 列名数组，1–4 条（给了 `residual_zh` 时上限收到 3 —— 残差占掉最上面那一段，配色只有 4 档，见 `MIX_SEG_COLORS`）。必须与 `total` **同 `unit`、同 `stock` 档**，否则硬失败 |
| `residual_zh` | 有残差时✓ | 残差段（= `total` − Σ`parts`）的名字 |
| `rhs_share` | | `parts` 里的一个列名，或字面量 `'residual'`：把那一段换成 0–ymax 的刻度在右轴上再画一遍 |
| `note` / `share_note` | | 分别追加到两张图的图注末尾 |

**同比口径**（CONTRACT §6.1）：

- `total` 是**流量** → 次轴是**单月同比**（当月对去年同月，本列除本列，不换列也不还原）。
  ⚠️ 这**不是**底座的默认 —— §6.1 第 1 条把 12 个月滚动合计的同比定为流量的默认，
  用单月要满足第 2 条的两个条件，`ex_mix_total` 两个都做到了：标题里写着「单月同比」
  （`tools/check_yoy_caliber.py` 的 R4 只认 title/ylab2/legend/yoy.name 四处），
  图注由 `mom_cost_zh()` 印出理由**连同实测代价**（两种口径的标准差、相邻月最大跳变、
  符号相反的月份数）。理由本身是「页面所有者要求全页统一口径」——
  一句可核对的事实，不是 §6.1 点名禁止的「看着更灵敏」。
- `total` 是**存量** → 次轴是**点对点同比**，标题带 `（存量，期末口径）`。
  那五个字不是修辞：`tools/check_yoy_caliber.py` 的 `_STOCK_TXT` 认它，认到了才豁免
  R1/R4；措辞与 `ex_stock` 逐字相同。
- ⇒ mix **不吃** `granularity` / `total_col` / `weight_col`。那三个是 §1.4 的 `ttm_yoy`
  用来把日均列还原成当月合计好滚 12 个月的；单月同比一步还原都不需要，
  留着就是死配置（写了会撞 §4 第一条的硬失败）。

**底座保证的五件事：**

1. **加总关系逐月复算，spec 说了不算。** 残差为负（分项之和 > 合计）→ 硬失败（子集关系
   不成立时占比会大于 100%，而图上只画成一根更高的柱）。残差 > `MIX_RESID_TOL`（1e-6）
   而没给 `residual_zh` → 硬失败（图会声称「堆叠 = 100%」而实际不是）。给了
   `residual_zh` 而残差恒为 0 → 也硬失败（恒为 0 的「其他」段会让读者以为存在一块
   查不到的业务）。收尾还有一道：各段之和必须逐格等于 100（容差 1e-6）。
2. **窗口只截不补。** `stacked_dual` 在 `DENSE` 名单里，窗口内一个 `null` 都不许有。
   底座取「合计与全部分项都有值的**末端连续段**」再与 `WIN_FROM` 取晚；不足 24 个月
   这张图整张不出（理由记进 `skipped`，构建日志里打印）。慢腿页每月初都会有一格
   「头条已发、慢腿没发」的空——右端自动退一格，不是故障。
3. **被 mix 吃掉的列不再进本组的常规对比图**（`self.mix_used`）：它们的水平值由合计柱
   交代、结构由占比图交代，画两遍是同一批数在同一页上出现两次。**只影响画图 ——
   汇总表与末尾核对表仍走 `groups[].cols` 全量。**
4. **存量 mix 排在第 ⑤ 段**（与本页其余存量图一起），流量 mix 排在第 ③ 段（组的位置上）。
   存量与流量不共轴，也不该在阅读顺序上互相插队。
5. **占比图不给右轴线**（除非显式 `rhs_share`）：各段之和恒为 100，段高本身就把每一块
   读出来了，再拿其中一段换个刻度画一遍是同一个数说两遍。例外只有一种，也正是
   `/exchanges-eu/` Ex2 立这条例外的理由：某一段常年只占几个百分点，在 0–100 的堆叠里
   它几个 pp 的变化根本量不出来。

**回归基准**（挑的是**不随窗口滚动而变**的两条结论，月份与期数刻意不写死 ——
窗口右端每个月都往前走一格）：`tmx` 的 `mx_adv_contracts` ≡ `mx_adv_futures_contracts`
\+ `mx_adv_options_contracts`，**图窗内逐月残差恰为 0** ⇒ 两段堆叠、**不许**给
`residual_zh`（给了就硬失败）。同页 `mx_adv_stir_futures_contracts` 的残差自
**2023-03**（一个历史事实，不随窗口变）起非零，量级在千分之二以内
⇒ **必须**给 `residual_zh`。两条都对不上就是这套复算被改坏了。

## 2. 底座产出什么

Exhibit 1 是汇总表，图从 2 起编号，末尾是核对表。顺序固定：

| # | 内容 | 图型 | 规则 |
|---|---|---|---|
| ① | 每条头条序列的全历史 + 近 3 年分位带 | `lines`（通栏，height 360） | 深蓝 = 序列；灰 = 近 36 个月 P90 上沿；浅蓝 = P10 下沿。全为正时纵轴从 0 起 |
| ② | 每条头条序列的同比 | `grouped_bars` | 含正负、有零线。比率列走百分点差。**不用 `diverging_bars`**（它的图例与表格列名在引擎里写死成 COST 文案） |
| ③ | 每组的多列对比 | 见下 | 组内先按 `unit` 分桶，一桶一张图。声明了 `mix` 且合计是流量列的组，先出「合计柱 + 占比堆叠」两张（见 §1.5），被 mix 吃掉的列不再进分桶 |
| ④ | 每条头条序列的季节性 | `seasonality` | 灰 = 过去最多 5 年同月均值，蓝 = 实际，13 个月窗口 |
| ⑤ | 每个 `stock: True` 的列 | `gs_bar` + 次轴同比 | 单独成图，图注写明期末口径与「不能与流量相加」。声明了 `mix` 且合计是存量列的组，这一段先出「合计柱 + 占比堆叠」两张（见 §1.5） |
| ⑥ | 每条 `decomp` | `bridge_bar` | 年度量价分解，见 §1.3。**追加在末尾** |
| ⑦ | 每条 `ttm_yoy` | `gs_bar` + 次轴 TTM 同比 | 见 §1.4。同样追加在末尾 |
| ⑧ | 近 13 个月核对表 | `table` | 本页单位，可与官方披露逐格对账 |

⑥⑦ **一律追加在全部既有 exhibit 之后**，不插进 ③ 里。插中间会让图号级联位移，正文与图注里所有「见 Exhibit k」的交叉引用一起错，而那种错不报任何异常。

③ 的分桶规则（全部由数据形状决定，不逐家手调）：

| 一桶里几列 | 画法 | 为什么 |
|---|---|---|
| 1 | `gs_bar`（水平值 + 次轴金色同比） | 一条线没有「对比」可言 |
| 2–5 | 窗口逐点稠密 → `lines_endlabels`；有缺口 → `lines`（不平滑、断笔） | 平滑图型会把 `null` 当 0，画出一条塌到零的假线，首尾为 `null` 还会抛 TypeError 让该卡片之后的图全不渲染 |
| >5 | `heat_matrix`，画的是**同比**不是水平值 | 数据色只有 6 个，第 6 条线必然与别人同色；而热力矩阵的色标是全表共用的 5/95 分位，水平值量级差几十倍时会被最大的那列吃掉整条色标 |

**为什么按 `unit` 分桶**：把 2 : 15 : 64 三个量级画在一根轴上，最小的那条振幅只占画布 1%，
等于白画（cboe 原 deck 的 Exhibit 9 就是这么错的）。所以一个 group 里写了两种单位，
底座会拆成两张图，而不是让你自己记得拆。

### 2.1 `gs_bar` 的分部堆叠（`ex.stacks`）**不由本底座产出**

引擎给 `gs_bar` 加了一个可选的 `stacks[]`：给了就把每根柱按业务分色，总额仍取 `values`
（字段契约见 `docs/CHART_KINDS.md` §3.6.1）。**`build/single.py` 一处都没用它，
本文的 SPEC 里也没有对应字段** —— 写了会撞 §4 第一条「有未知字段」的硬失败。

理由是「加总关系」这件事本底座默认拿不出保证：`groups[].cols` 里的列是**彼此独立的
序列**（先按 `unit` 分桶，同桶的几条只是量纲相同），谁也不是谁的一部分，堆起来的柱高
没有指称；而 `stacks` 要求「各段之和逐格恒等于总额」。硬堆出来的图不会报错，
只会画出一根谁也解释不了的柱。

**⚠️ 「默认拿不出保证」不等于「永远拿不出」。** 拿得出的时候，正确做法是
**把它写下来并让底座复算** —— 那就是 §1.5 的 `groups[].mix`：spec 显式声明
`total` 与 `parts`，底座逐月撞恒等式，对不上就硬失败。`mix` 出的是
`stacked_dual`（占比恒为 100%）而不是 `gs_bar` 的 `stacks`，两者的区别是
**分母**：前者画结构（每根柱一样高），后者画规模（柱高 = 总额）。
本底座至今仍不产出后者。

台湾半导体月度营收那 7 页走的是第三条路：`build/mrbase.py` + `build/mrspecs/<t>.py`，
分部列在 SPEC 的 `segments` 字段里显式声明，与合并营收本来就是披露层面的加总关系。
配色走那边的共用常量 `_SEG_COLORS`，堆叠段 / 占比线 / 全历史分部线三张图同色。

## 3. 门槛：什么时候**不**出页

- 共同最新月 = 各头条列末月里最早的那个，再往回找到最近一个**全部头条列都有值**的月份
  （最多回溯 12 个月）。它就是 `data_through`。
- `slow_cols` **一律不参与**这个判定 —— 否则一条天生晚发的腿会把整页拖住。
- 共同连续历史必须 ≥ 24 个月（同比 + 一年缓冲），否则不出页。

算不出时：打印原因、**退出码 0**、已有的 `data/<t>.js` 原地不动。
这类情形多数是「这个月还没发全」，下个月自愈；硬失败会让 `monthly_run.py` 每天记一次 FAIL，
喊狼来了喊到没人看。

## 4. 硬失败清单（退出码 1，要人去改）

写错 spec 与「等数据」是两回事，前者不会自愈，所以一律响：

| 症状 | 报错 |
|---|---|
| spec / group / 列配置里有未知字段 | `有未知字段 ['stocks']` |
| 缺必填字段 | `缺必填字段 ['unit']` |
| `col` 不在 CSV 里 | `series/<csv> 缺列 [...] —— 写 spec 之前先 head -1 …` |
| `fmt` 不是引擎实有的名字 | 列出全部 18 个可用名 |
| 0–1 的小数比率配了 `pct*` 却没给 `scale` | `最大绝对值只有 0.19，看着是 0–1 的小数比率…请加 'scale': 100` |
| `slow_cols` 里的列名拼错 / 没出现在 headline、groups 里 | 慢腿声明会静默失效，所以硬失败 |
| 某列既是头条又是慢腿 | 头条定义门槛，慢腿被排除在门槛外，两者不能同时成立 |
| `ticker` 与文件名不一致 | 目录名 = data 文件名 = `payload.ticker` 必须逐字相同 |
| CSV 有重复月份 / 没有 `month` 列 | 位置对齐全靠月份索引 |
| payload 里出现 NaN / `$nanbn` 这类展示串 | 由 `build/payload_guard.py` 拦下，旧文件原地不动 |
| `decomp.kind` 不是三类之一 | 派生量含义随类别完全不同，措辞混用会把「订单碎片化」印成「价格下跌」 |
| `decomp.year_label` 不是 `'start'` / `'end'`，或日历年写了 `'end'` | 标签集体偏一年而图形正常，没有自动判据能发现 |
| `weight_col` × 日均列 与 `*_total_col` 对不上（相对偏差 > 1e-6） | 两列不是同一套交易日口径，还原出来的当月合计不可信 |
| 量价分解的任一道恒等式残差 > `1e-9` | 六道护栏见 §1.3 / §1.3.1；图上看不出恒等式不成立，所以宁可整页不出 |
| `mix` 的分项之和**超过**合计（残差为负） | 子集关系不成立时占比会大于 100%，而图上只画成一根更高的柱 |
| `mix` 有残差（> `1e-6`）却没给 `residual_zh` | 那张图会声称「堆叠 = 100%」而实际不是，是一句静默的假话 |
| `mix` 给了 `residual_zh` 而残差恒为 0 | 一条恒为 0 的「其他」段会让读者以为存在一块查不到的业务 |
| `mix` 的分项与合计 `unit` 不同 / 一个流量一个存量 | 占比 = 分项 ÷ 合计，两边不同单位时这个比值不指代任何东西；流量与存量不能相加 |
| `mix` 的合计是存量列却给了 `granularity` / `total_col` / `weight_col` | 那三个字段是给「12 个月滚动合计」用的，而 12 个月末快照相加不指代任何量（CONTRACT §6.1 第 4 条） |
| `mix` 的合计是流量列却没给 `granularity` | 次轴那条滚动同比要先把柱还原成当月合计，底座猜不出来，猜错会在图注里印出一句关于口径的假话 |
| `mix` 的 `total` / `parts` 指向没在本 spec 里声明过的列 | 列配置只在 `groups[].cols` 声明一次，mix 写的是列名；拼错会让整张图静默消失 |
| 同一段图注里出现**互相排斥的口径断言** | `caliber_audit()`：底座已两次在图注里无条件印出对某些页为假的口径断言（「本身即当月合计口径，未做还原」印在日均列上；「柱是日均，已除过交易日数」印在月合计列上）。这类缺陷 `verify_pages.py` 结构性查不出来（两次都是 0 ERROR 通过的），只能靠生成端自检。**凡是断言「这一列是日均 / 是月合计 / 已除过交易日 / 已做过还原」的措辞，一律由 `granularity` + `total_col` + `weight_col` 派生，不许无条件写进 f-string** |

**不硬失败、但会说出来**的三种：

- 某列整列为空 → 从图与表里剔除，打印 + 写进「口径与方法说明」（不画空图）
- **某列在窗口内恒为 0** → `ex_single` / `ex_lines` / `ex_stock` 一律返回 `None`：
  **图不出，但那一列仍留在核对表里**，并在「口径与方法说明」里点名（含它最后一次非零
  是哪个月、多少）。理由：引擎给柱图的纵轴上界写死成 `max × 1.22`，max 也是 0 时上下界
  重合、`Y(v)` 变成 0÷0，坐标全成 NaN/±Infinity，画出来是一团糊在画布角上并越出卡片的
  东西（实测某页越界 8px、53 个非有限坐标属性），不是一排零高的柱。
  **spec 层不必再为此把列从 `groups` 里摘掉** —— 摘掉会让那一列同时从核对表消失，
  而「官方报的就是 0」正是核对表要能对上的事实。也**不要**用 `stock: True → False`
  绕开除零：那是把期末存量谎报成流量，代价比这个 bug 大。
- CSV 缺某几个月的行 → 补成空行，图在缺口处断笔，打印 + 写进说明（不把缺口连成直线）
- 非头条列缺最新月 → 那一格是 `null`，图上断笔、表里「—」（不拖住整页）
- `decomp` / `ttm_yoy` 声明了却画不出来（完整年度不够、年度合计非正、窗口内恒为 0）→ 跳过那一张，打印 + 写进「口径与方法说明」并点名原因（静默少一张图与「这家本来就没这张图」在页面上长得一模一样）
- `mix` 画不出来（合计整列为空、窗口内恒为 0、合计与全部分项都有值的连续窗口不足 24 个月、某月合计 ≤ 0）→ 跳过，理由记进 `skipped`、构建日志里打印。**这几种都是「等数据」不是「spec 写错」**，与上面那张表里的六条硬失败分得很开

## 5. 写一份新 spec 的步骤

1. `head -1 series/<t>.csv | tr ',' '\n' | nl` —— 列名逐个核对，别凭印象写。
2. 选头条：**历史长、发布快、无空洞**的 1–3 条。它决定 `data_through`，选错整页跟着它停。
3. 分组：一组一个主题；组内单位不同没关系（底座会拆），但同组同单位读起来最顺。
4. 存量列标 `stock: True`（未平仓、托管资产、市值这类期末截面值）。
5. 组里若真有「合计 ≡ 各分项之和」这层关系，给它加 `mix`（§1.5）——
   底座会逐月复算，残差对不上就硬失败，比画一张多列折线图信息量大得多。
   **别为了凑一张占比图去声明一个并不成立的加总关系**：那正是这道复算要拦的东西。
6. 慢腿列写进 `slow_cols`（发布比头条晚的腿，例如季度才出的托管规模）。
7. 断点优先指向 CSV。
8. `python3 build/single.py <t>` 跑一遍，看打印出来的 headline 与 exhibit 数对不对。
9. `python3 build/verify_pages.py --data-only` 复核（0 ERROR 才算过），
   再跑一次 `python3 tools/visual_qa.py --page <t>`（0 🔴 才算过）与
   `python3 tools/check_yoy_caliber.py --page <t>`（0 🔴 才算过）。

可用格式器（`assets/charts.js` 实有的 18 个，多一个少一个都会被静默退回 `f1`）：

```
f0 f1 f2 f3        29 / 29.2 / 29.24 / 29.241
f0c int            1,234（千分位）
usd0 … usd4        $29 … $29.2412
pct0 pct1 pct2     29% / 29.2% / 29.24%      ← 期望百分数刻度，0.29 要先 scale 100
pct0z              同 pct0，但 |v|<0.5 印 0%
pp0 pp1            +5pp / +5.1pp（自带符号）
x0                 29X
```

数据色只有 `NAVY` `BLUE` `MBLUE` `GRAY` `GREEN` `GOLD` 六个；`RED` 是断点与截轴离群值专用色，
**不做数据色**。这两条由底座自己保证，spec 里没有配色字段。

## 7. 底座与手写生成器那 11 家的关系

既有 11 家（cme / cboe / hkex / ibkr / schw / lpla / hood / msci / spgi / cost / axp）
仍各自跑 `build/<t>.py`，**本轮一行都没改**。
（原来这里写的是 12 家、含 `tsm`；2026-08 台湾半导体接入后 `tsm` 已改走
`build/mrbase.py` + `build/mrspecs/tsm.py` 那条路，`build/<t>.py` 只剩一个薄壳入口。
仓库里现在有**三条**生成器路径：本文的 `single.py`、各家手写的 `build/<t>.py`、
以及 `mrbase.py`，`monthly_run.builder()` 按「文件在不在」逐条试。）
底座里的 `mlab` / `nz` / `nz_txt` / `LN` /
`load` / `yoy_line` / `yoy_rhs` / `qlab` / `to_monthly` / `tail_contiguous`
就是从 cme / cboe / hkex 那三份重复实现收敛来的（口径取最严的一份）。

将来要迁的话，做法是逐家把 `build/<t>.py` 换成 `build/specs/<t>.py`，并**逐字节比对**
新旧 `data/<t>.js`（除首行构建日期）；比对不上就说明底座还缺那家的某个口径，
先补底座，不要在 spec 里塞逻辑。分位（`3Y %ile`）一律走 `build/pctile.py`，
那是全站唯一的实现 —— 各页各写各的，正是同一条序列在两页被判定相反的原因。
