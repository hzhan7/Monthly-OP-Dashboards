# pandas —— 28 个模块（fetch/* 的解析、build/* 的序列对齐与 Period 索引）；
#   COST 的解析管道（fetch/cost_release.py 的 pd.read_html）曾住在 /COST月度销售 skill 里、
#   由 skill 与本仓库共用；skill 已删除、代码已搬进本仓库，所以「两边要同版本」这条约束没了。
#
#   ⚠️ 3.0 是**行为破坏性大版本**，别顺手升也别顺手降：
#   1. `astype(str)` 产出 StringDtype(storage='python', na_value=nan)，**NaN 仍是 float**，
#      不再像 2.x 那样被转成字符串 'nan'。凡是 `astype(str)` 之后直接 ' '.join / 假定元素都是 str
#      的地方，在 3.0 下必抛 TypeError。COST 的 comp 表解析
#      （fetch/cost_release.py 的 parse_release）就是这么死的 —— GlobeNewswire 的表必然带空单元格，
#      所以是 100% 复现，不是偶发。现已在那里补 `.fillna('nan')` 修好。
#   2. read_csv / read_html 读出的文本列默认是 StringDtype 而不是 object dtype。
#      任何 `dtype == object` 的判断在 3.0 下都不再成立（本仓库目前没有这种写法，别新写）。
#   3. Copy-on-Write 成为默认且不可关闭，链式赋值（df[a][b] = v）静默无效不再报警。
#      本仓库目前没有链式赋值（已核查），新增代码请一律用 .loc 单步赋值。
#   降到 2.x 同样要重跑一遍：上面那处 `.fillna('nan')` 在 2.x 下是无害 no-op（2.x 的
#   astype(str) 已经把 NaN 变成 'nan' 了），所以 2.x/3.x 双向兼容 —— 但没在 2.x 上实测过。
pandas==3.0.5
